# ORANGIA — CONCEPTION FINALE DE LA BASE DE DONNÉES

**Version : 1.0 — Novembre 2026**  
**SGBD : PostgreSQL**  
**Application : Java 21 / JavaFX / Maven**  
**Architecture : MVC — DAO — Service**

---

# 1. Organisation générale

La base de données Orangia est organisée autour de quatre espaces :

- Administrateur
- Responsable de Ferme
- Agent RH
- Comptable

Elle couvre les modules suivants :

1. Authentification et gestion des utilisateurs.
2. Gestion des fermes et parcelles.
3. Gestion du personnel et des affectations.
4. Gestion des présences et corrections.
5. Gestion des salaires et paiements.
6. Gestion des récoltes.
7. Gestion des clients et expéditions.
8. Gestion des dépenses et demandes.
9. Documents et notifications.
10. Journal d'activité.
11. Paramètres système.
12. Calcul du stock.

## Conventions techniques

- Clés primaires : `BIGINT GENERATED BY DEFAULT AS IDENTITY`.
- Clés étrangères : `BIGINT`.
- Montants et quantités : `NUMERIC`.
- Dates métier : `DATE`.
- Horaires : `TIME`.
- Traçabilité : `TIMESTAMPTZ`.
- Données structurées complémentaires : `JSONB`.
- Suppression physique interdite lorsqu'un historique métier doit être conservé.
- Les opérations importantes sont protégées par des transactions.

# 3. Vue de calcul du stock

## V_STOCK_FERME

Cette vue sera créée dans la phase de finalisation.

Elle ne représente pas une table avec des données modifiées manuellement.

| Attribut calculé | Description |
|---|---|
| id_ferme | Ferme concernée |
| total_recoltes | Total des récoltes enregistrées et non annulées |
| total_expeditions | Total des expéditions confirmées et non annulées |
| stock_disponible | Total récoltes - total expéditions |

Formule :

`Stock disponible = Récoltes valides - Expéditions confirmées non annulées`

Les opérations de confirmation doivent être transactionnelles et protégées contre les confirmations simultanées qui dépasseraient le stock disponible.

# 7. Architecture Java recommandée

Organisation logique :

- `model` : entités métier.
- `dao` : interfaces et implémentations d'accès aux données.
- `service` : règles métier, validation et transactions.
- `controller` : gestion des interactions JavaFX.
- `util` : connexion, sécurité, alertes et fonctions communes.

Les entités Java ne doivent pas contenir de SQL.

Les Services contrôlent les règles métier et les autorisations.

Les DAO utilisent des requêtes adaptées aux droits de chaque rôle. Les données financières ne doivent jamais être retournées dans les projections destinées au Responsable.

# 8. Règles à respecter pendant la création du schéma

1. Ne pas créer une deuxième fois une table qui existe déjà.
2. Ne pas supprimer les anciennes tables historiques.
3. Ne pas utiliser FLOAT pour les montants et quantités.
4. Ajouter les index nécessaires aux clés étrangères et recherches fréquentes.
5. Utiliser des contraintes UNIQUE pour les références et les règles d'unicité.
6. Utiliser ON DELETE RESTRICT pour les données qui ont un historique métier.
7. Vérifier les transitions de statuts dans les Services.
8. Utiliser des transactions pour les paiements et confirmations d'expédition.
9. Préserver les données historiques lors des transferts d'ouvriers.
10. Tester chaque migration sur la base de test isolée avant validation.
